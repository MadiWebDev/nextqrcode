# Deployment — Social Media Calendar

## Shape

The product ships inside the existing Next.js app (repo
`MadiWebDev/nextqrcode`) and deploys with it on Vercel. There is no
separate service, database or environment variable for this product.

- Host: `socialcalendar.freeqrcode.tools` (DNS + Vercel domain, owner's
  step — same pattern as the invoice and image-resizer subdomains).
- Routing: `src/proxy.ts` maps the host to `src/app/socialcalendar-site/`
  (one additive host block; extensioned paths are exempt, which is why
  the PWA manifest and service worker are root-level route handlers:
  `src/app/socialcalendar-manifest.webmanifest/route.ts` and
  `src/app/social-sw.js/route.ts`).
- Sitemap: section 10 is generated by `src/app/sitemap.ts` and indexed
  from `public/sitemap.xml`; after deploy, confirm
  `https://freeqrcode.tools/sitemap/10.xml` returns the 8 socialcalendar
  URLs and submit the subdomain in Google Search Console.

## Pre-deploy checklist

1. `npx tsc --noEmit` — clean.
2. `npx vitest run` — full suite green.
3. `node scripts/check-socialcalendar-seo.mjs` — PASS.
4. `npm run build` — exit 0.
5. Serve smoke on all four hosts (apex, invoice, imageresizer,
   socialcalendar) — 200s with correct titles, plus `/app`, one guide,
   `/socialcalendar-manifest.webmanifest`, `/social-sw.js`.

## Rollback

The product is additive: reverting its commits removes the site
without touching the other subdomains (shared files changed additively
only: one proxy host block, one sitemap section, scoped CSS rules).
User data lives in visitors' browsers and is unaffected by deploys.
